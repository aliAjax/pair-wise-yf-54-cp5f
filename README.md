# pair-wise-yf-54 博物馆借展点交：多平板离线签字与联网合并

借展现场多台平板协同：保管员断网继续给展品做环境检查、签字与差异登记，网络恢复后按
**记录编号 + 字段版本**合并；冲突读数双版保留并标明来源，复核完成前禁止推进。

## 技术栈
Vue 3 + TypeScript + Vite + Vuetify + Pinia + Vue Router + Axios + VueUse + VeeValidate + Zod + Vue I18n。

## 已实现规则（对应现场要求）

1. **断网继续签字**：断网开关下仍可改读数、登记差异、签字；所有操作以操作日志形式
   暂存本机 `queue`（localStorage 持久化），记录操作设备、时间与字段版本。
2. **签字快照**：每条签字记录当时三个环境读数（温度/湿度/照度）的字段版本号与全部
   未解决差异编号，计算指纹。任一读数版本变化或差异被处理，`revalidateSignatures`
   立即把原签字置为失效并给出**复核原因**（如“温度读数已从 v1 变更为 v2”）。
3. **复核门禁**：`gateReason` 同时校验「冲突读数待复核 / 未解决差异 / 失效签字 /
   缺保管员或借展方有效签字」，任一不满足都不能推进阶段；推进操作入队，合并端再次
   校验，避免绕过。
4. **按记录编号 + 字段版本合并**（`src/domain.ts` 纯函数，`scripts/verify.ts` 覆盖）：
   - 每个读数是 `FieldVersion { value, version, base, origin }`；
   - `base === 对端当前版本` 为线性快进，直接采用；
   - 同父分叉且读数不同（含同版本号不同值）为冲突，**两版都保留**在
     `pendingVariants` 并标明来源平板与版本，任何一方都不被覆盖；
   - 同值重复投递（包括重试）**仍算一项**，不追加变体；
   - 复核人选定一版后生成 `reviewed` 权威版本，同步到他板时权威快进并清掉待复核项。
5. **失败保留原操作与重试队列**：合并失败（网络注入或门禁拒绝）的操作原样留在队列，
   累计 `attempts` 与 `lastError`；界面“等待处理项”标注重试次数与原因，可手动重试。
6. **重试不覆盖他人确认**：差异已被其他平板确认时，重试操作幂等成功但**不改动**
   确认人与处理意见。
7. **界面展示**：顶部断网/队列提示与合并入口、四个指标卡（含“待复核记录”）、
   “复核工作台”页、详情弹窗顶部的复核原因、读数版本/来源、冲突双版的“选定此版”、
   签字有效/失效状态与原因、底部等待处理队列与合并日志。

## 多平板演示路径
顶栏切换平板 A/B/C 与断网开关；在展品详情底部可模拟：
- 两板断网期间改出温度分叉 → 联网合并看到双版与复核入口；
- 他板借展方签字到达；
- 注入一次网络失败 → 操作进入重试队列，重试后成功；
- 他板先确认差异 → 本机重试不覆盖他人结论。

## 命令
```bash
npm install
npm run dev       # 开发端口 62019
npm run verify    # 领域合并/门禁规则断言（14 项）
npm run build     # vue-tsc 类型检查 + 生产构建
```

## 代码结构
- `src/domain.ts`：字段版本、签字快照、门禁、三方合并、冲突保留、复核裁定（纯函数）。
- `src/stores/exhibition.ts`：离线操作队列、收件箱、合并编排、失败重试、场景模拟。
- `src/App.vue`：点交列表、复核工作台、差异页、展品详情（读数版本/签字/差异/推进）。
- `scripts/verify.ts`：需求场景的可执行断言。
